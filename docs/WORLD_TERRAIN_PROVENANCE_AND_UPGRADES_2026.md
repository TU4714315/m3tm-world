# M3TM.WORLD terrain provenance and modern DEM upgrade gate
Audited: 2026-09-30. This document distinguishes **already working tiles** from **modern datasets requiring integration**. It is not a claim that Copernicus/NOAA/USGS tiles have been deployed.

## Why the linked Tilezen attribution document does not add new toggles
The user-linked `tilezen/joerd/docs/attribution.md` lists legal credits for the *input elevation datasets* inside a composite Mapzen terrain tile service, not plug-and-play map layers. Individual source credits cannot be used to infer that M3TM renders every underlying dataset at its full native resolution. Tilezen's own `docs/data-sources.md` explains geographic/zoom source mixing and input oversampling. New source layers require tiles, a renderer, correct datum/units and actual provider acceptance.

## Active, source-backed deployment
- **Current terrain:** public AWS Open Data `elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`, Mapzen/Tilezen. One existing MapLibre 6 renderer, existing cancellable two-request/8 MiB LRU loader.
- **Rendering:** Terrarium RGB/256 px tiles, active only at viewport zoom 10+ after motion settles, up to source zoom 10. `MapLibre raster-dem` terrain exaggeration 1. No elevation download at world overview zoom; zooming out releases terrain resources. Terrain zoom is **not the native input resolution**.
- **Source age:** Tilezen's composite includes SRTM, historical ETOPO1/GMTED, some country high-resolution inputs and ArcticDEM. Freshness and spatial quality vary per tile; never call this a 2026 global 30-m DEM or a live observation.
- **Credits:** `https://github.com/tilezen/joerd/blob/master/docs/attribution.md` and `https://github.com/tilezen/joerd/blob/master/docs/data-sources.md`; source registry `https://registry.opendata.aws/terrain-tiles/`. MapLibre native attribution displays the selected basemap, satellite imagery and active DEM source credits. Credits must remain visible, clickable, and unhidden by global CSS.
- **Imagery is independent:** the satellite basemap currently comes from Esri World Imagery, **not** a current live satellite stream. CARTO/OSM supply other map styles. Imagery credits are attached to the raster source only when that layer exists.

## More recent public elevation sources considered
| Provider and dataset | Actual public product | Difference / constraints | Present runtime state |
| --- | --- | --- | --- |
| **NOAA ETOPO 2022** | Global 15-arcsecond Ice Surface and Bedrock GeoTIFF/NetCDF elevation/bathymetry grids, replacing historical ETOPO1 | Current direct runtime expects Web Mercator PNG Terrarium. Needs clipped/derived raster conversion, tiles, vertical datum checks, land/ocean mosaic rules and NOAA citation. Not a navigational-depth chart. | **Candidate: not deployed** |
| **Copernicus DEM GLO-90** | Global 90-m **digital surface model** distributed as public cloud-optimized GeoTIFFs, from the 2021 release | Surface includes buildings/vegetation; not interchangeable with bare-earth DEM. Needs format conversion, terrain rights/coverage review, and end-to-end tests. | **Candidate: not deployed** |
| **Copernicus DEM GLO-30 Public** | 30-m public DSM **where released**; AWS public dataset excludes some country tiles | Public AWS product and the Copernicus Data Space Ecosystem (CDSE) **30-m View Service** have distinct access paths. CDSE 30-m view access became category-restricted in July/August 2026 and requires the appropriate CCM user access. Do not put restricted data or credentials in client code or assume global public 30-m coverage. Tile only under the correct access terms. | **Candidate: not deployed** |
| **USGS 3DEP S1M** | Newly added seamless 1-m COG elevation tiles for US regions, production began mid-2025 | Regional progressive availability only. Needs regional replacement mosaic and coordinate/datum handling. At world overview, full global use makes no sense. | **Candidate: not deployed** |

## Upgrade design and acceptance (no silent swaps)
1. Choose a use case/region. For **ocean relief**, consider a limited zoom ETOPO 2022 derived source. For **public 90-m global land cover**, evaluate GLO-90, documenting DSM versus terrain differences. For authorized 30-m areas, evaluate public GLO-30 coverage only; for the US, consider 3DEP where tiles exist.
2. Record access/licensing **by dataset**; compare a known test location to the current Mapzen baseline. Verify vertical datum, no-data semantics, shorelines and regional coverage. Incomplete regions must continue to use the already working Mapzen base rather than black placeholders.
3. Offline preprocess authorized Cloud Optimized GeoTIFFs to **Terrarium 256-px Web Mercator tiles** or a compatible, tested alternative. Validate elevation encoding, bounds, deterministic tiles, checksum, native resolution and attribution. Do not request giant COGs directly from every public mobile client.
4. Publish clipped tiles behind a controlled, cached CDN with versioned paths, rate limits, strict public/private separation and health probe. Keep existing Mapzen fallback; avoid making a newer provider the default until actual decoded elevation tile QA passes.
5. Test map startup at world zoom (0 terrain requests), idle zoom 10 (only 1–2 concurrent real DEM requests, decoded PNG and source `ready`), re-enable/retry, mobile 390×844, globe→regional projection, satellite style switch and no horizontal overflow. Preserve the APP bridge and WORLD source-layer behavior.
6. Release a separate PR with the **real public tile artifact and live browser tests**, not a new toggle pointing to an unconverted or restricted upstream GeoTIFF.

**Acceptance for this audit's attribution fix:** At desktop and mobile, default CARTO/OSM or satellite raster source credits must render in the map, stay clickable, and remain visible in both standalone WORLD and the APP iframe. When DEM is enabled and reaches regional zoom, Tilezen/Mapzen credits must appear as well. Disabled DEM should generate no requests to S3. Runtime evidence must confirm this after production deployment; passing CI alone is insufficient.
